# 领域入门前后端接口与展示方案

> 日期：2026-07-28
> 面向对象：前端开发、后端联调、项目交接
> 契约版本：领域入门输出 Schema V1，质量策略 `domain-quality-v1.3.0`

## 1. 交接结论

`domain_onboarding` 有前置知识、发展阶段、学习路线、论文、证据和质量记录等多类对象，长期不适合只作为普通聊天气泡展示。建议后续前端建立与论文精读同级的独立工作台。

当前仓库仅保留后端生成接口、本交接方案和完整契约示例，不包含领域工作台的具体 HTML、CSS 或 JavaScript 实现。推荐的未来接口与路由为：

```text
GET  /app/domain-onboarding   领域学习工作台
POST /domain_onboarding      同步生成接口
POST /paper_reading          从论文卡片导入精读
```

未来实现时，当用户在聊天页选择“领域入门”并提交，前端可将查询写入临时本地状态，然后跳转到：

```text
/app/domain-onboarding?query=<URL encoded query>
```

工作台可自动开始生成，并展示“需求解析 → 规划 → 检索 → 生成 → 质量检查”进度。

## 2. 请求契约

### 2.1 HTTP 请求

```http
POST /domain_onboarding
Content-Type: application/json
```

```json
{
  "session_id": "web-2f8e2a62",
  "content": "我已经学过 Transformer，希望六周入门 RAG，并完成一个基线实验",
  "user_id": "local-web",
  "metadata": {
    "background": ["Python", "Transformer"],
    "known_concepts": ["Python", "Transformer"],
    "goal": "建立 RAG 知识框架并完成基线实验",
    "time_budget_weeks": 6,
    "preference": "experiment_first"
  }
}
```

`metadata` 全部可选。前端不应发送空数组、空字符串或非正整数时间预算。`preference` 只能为 `balanced`、`theory_first` 或 `experiment_first`。

### 2.2 HTTP 包装层

Gateway 返回 `ChannelMessage`，真正的业务对象在 `content` 中：

```ts
type DomainOnboardingEnvelope = {
  session_id: string
  channel: 'web'
  direction: 'outbound'
  mode: 'domain_onboarding'
  content: DomainOnboardingResponse
}
```

前端需同时兼容 `content` 为对象和 JSON 字符串的情况，但新 Gateway 默认返回对象。

## 3. 返回状态与页面行为

| `content.status` | 是否可有完整输出 | 前端行为 |
|---|---:|---|
| `ok` | 是 | 进入工作台，标记“质量通过” |
| `quality_warning` | 是 | 正常展示，黄色提示需要复核 |
| `quality_failed` | 是 | 展示但标记为不可直接信任，展开硬门槛失败项 |
| `invalid_input` | 否 | 回到输入表单 |
| `planning_failed` | 否 | 错误页，允许修改范围 |
| `retrieval_failed` | 否 | 明确说明没有可验证论文，不用模型记忆补造 |
| `generation_failed` | 否 | 错误页，允许重试 |
| `timeout` / `cancelled` | 可能 | 如无输出显示错误；如后续支持 partial output，应标记为未完成 |
| `internal_error` | 否 | 错误页，不向用户暴露秘钥或配置 |

不能只根据 HTTP 200 判定成功；必须继续检查 `content.status`。

## 4. 工作台数据映射

| 展示区域 | 后端字段 | 要点 |
|---|---|---|
| 顶部领域摘要 | `domain`, `text`, `policy_version` | 策略版本用于实验追溯 |
| 学习者画像 | `learner_profile` | 展示后端实际解析值，不只展示原表单 |
| 前置知识 | `prerequisites[]` | 使用 `prerequisite_id` 作为稳定键 |
| 发展脉络 | `development_stages[]` | 展示动机、概念、技术、开放问题和绑定论文 |
| 当前全景 | `current_landscape` | 问题与子方向分组展示 |
| 学习路线 | `learning_path[]` | 按 `step` 显示目标、活动、完成标准和论文 |
| 论文阅读清单 | `papers[]` | 按 `reading_priority` 过滤，`paper_role` 仅表示学术角色 |
| 阅读指导 | `representative_papers[]`, `learning_path[].papers[]` | `contribution` 和 `reading_focus` 是教学字段 |
| 证据声明 | `evidence_claims[]` | 证据强度由 `support_type` 决定 |
| 质量状态 | `quality` | 分数与硬门槛需分开展示 |
| 修复审计 | `quality_attempts`, `repair_record` | 默认折叠，保留可解释性 |
| 实验图谱 | `knowledge_graph` | 只在后端返回时显示，不是 V1 主导航 |

### 4.1 论文反向索引

未来前端实现时建议建立下列索引，不依赖标题字符串匹配：

```ts
papersById: Map<paper_id, SelectedPaper>
stagesByPaper: Map<paper_id, DevelopmentStage[]>
stepsByPaper: Map<paper_id, LearningStep[]>
evidenceByPaper: Map<paper_id, EvidenceClaim[]>
prerequisitesByPaper: Map<paper_id, Prerequisite[]>
```

点击阶段、路线或证据中的论文标签时，应定位并高亮右侧论文卡片。

### 4.2 论文优先级与角色

- `reading_priority`: `core` / `recommended` / `optional` / `extended`，决定学习顺序和过滤器。
- `paper_role`: `survey` / `foundational` / `method` / `evaluation` / `application` / `frontier` / `other`，用于解释论文的学术作用。
- `is_canonical`: 来自版本化核心论文表的匹配结果，可显示 `Canonical` 标签，不等价于引用量最高。

## 5. 质量与修复展示规则

1. `quality.passed_hard_gates === false` 时，即使总分较高也不得显示“通过”。
2. `quality.state` 为 `passed` / `warning` / `failed`，对应绿、黄、红。
3. `quality.hard_gates[]` 显示 `status`、`score`和 `threshold`；不只显示 issue 数量。
4. `quality.issues[]` 显示 `dimension`、`target_path`、`message` 和 `recommended_action`。
5. `repair_record.actions[]` 显示动作类型、状态和 `changed_paths`；`decision` 说明为何保留原结果或修复结果。
6. 质量与修复区域默认折叠，但 `quality_failed` 后续可改为默认展开。

## 6. 与论文精读的交接

未来实现论文卡片时，当 `papers[].arxiv_id` 存在，建议显示“导入论文精读”：

```json
{
  "action": "upload_paper",
  "session_id": "",
  "paper_id": "",
  "content": "",
  "pdf_url": "https://arxiv.org/pdf/2005.11401.pdf",
  "metadata": {
    "source": "domain_onboarding",
    "domain": "检索增强生成",
    "source_paper_id": "paper-rag"
  }
}
```

未来导入成功后，前端应将 `content.data.paper_id` 写入 `paper_reading_paper_id`，清除旧 `paper_reading_session_id`，再跳转 `/app/paper-reading`。只有 DOI 或非 PDF 来源页时，仅展示“查看来源”，不应把 HTML 页当作 PDF 上传。

## 7. 本地恢复契约

建议未来工作台使用单个版本化快照：

```text
key: domain_onboarding_workspace_v1_3
schema_version: 1.3
value: { saved_at, request, result }
```

读取时应校验 `schema_version`。未来 Schema 升级时新建 key 或实现显式迁移，不对旧对象猜测补字段。该方案是浏览器级快照，不是跨设备学习进度。

## 8. 完整输入输出示例

- 完整请求：见本文第 2.1 节。
- 完整 Gateway 返回：[`examples/domain-onboarding-complete-response-v1.3.json`](examples/domain-onboarding-complete-response-v1.3.json)。

## 9. 当前边界与后续扩展

当前仓库保留：

- `POST /domain_onboarding` 后端接口及完整结构化输出。
- 本文的前后端数据映射、状态和交互建议。
- 可直接用于前端 Mock 的完整输入输出示例。

尚未实现：

- 独立输入页、生成过程页、错误页和三栏工作台。
- 论文反向索引、优先级过滤和跨区域定位交互。
- 版本化 `localStorage` 恢复。
- 从领域入门论文卡片导入论文精读。

后续可扩展：

- 将同步 POST 升级为任务 ID + SSE/轮询，展示后端真实阶段进度并支持取消。
- 增加服务端路线持久化和跨设备学习进度。
- 将论文精读导入拆成后端任务，避免大 PDF 解析长时间占用浏览器请求。
- 知识图谱经质量门槛通过后，再作为学习路线的可视化辅助层。
