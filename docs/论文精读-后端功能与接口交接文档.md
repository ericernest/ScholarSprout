## 2. 后端模块地图

| 文件/目录 | 作用 |
|---|---|
| `gateway/app.py` | FastAPI gateway；注册 `/paper_reading` 和 `/paper_reading/uploads/{paper_id}.pdf` |
| `channels/web.py` | Web 请求转 `ChannelMessage`；论文精读模式传完整 body |
| `handlers/paper_reading_handler.py` | 框架 handler 稳定入口，委托到 `handlers.paper_reading.handler` |
| `handlers/paper_reading/handler.py` | 论文精读 action 路由和主业务逻辑 |

| `handlers/paper_reading/harness/storage.py` | paper、session、KG、upload PDF 本地持久化 |
| `handlers/paper_reading/harness/session.py` | session、checkpoint、progress、active skills |
| `handlers/paper_reading/harness/fork_merge.py` | fork 子会话和 merge |
| `handlers/paper_reading/kg/models.py` | 13 类节点、9 类边 |
| `handlers/paper_reading/kg/engine.py` | KG 内存图引擎 |
| `handlers/paper_reading/kg/builder.py` | 整篇论文一次性 KG 构建 + 渐进展开 |
| `handlers/paper_reading/kg/query.py` | KG 驱动问答 |
| `handlers/paper_reading/postprocessors/*.py` | 8 个 Skill 输出的 Python 后处理，不参与 Skill 注册 |
| `skills/builtin/reading/*/SKILL.md` | 8 个 Skill 的 prompt 定义 |
| `tools/builtin/*paper*/*kg*` | agent 可调用工具 |
| `tests/test_paper_reading/verify_functional.py` | 新增功能验证脚本 |

论文源行为：

- arXiv API 全进程限制为单请求序列，任意两次请求至少间隔 3 秒，并识别 `Retry-After`。
- `2506.07398`、`arxiv:2506.07398` 和 arXiv `abs/pdf` URL 会走精确 ID 查询，不再作为全文关键词搜索。
- 精确 ID 先通过 OpenAlex 按 arXiv 落地页解析；仅在尚未收录时再查 arXiv 和 Semantic Scholar。
- 普通关键词搜索仍并行使用 arXiv 和 Semantic Scholar；两者均失败时才使用 OpenAlex 搜索。
- 可选环境变量 `SEMANTIC_SCHOLAR_API_KEY` 和 `OPENALEX_API_KEY` 会自动加入对应请求。
- 所有目标源失败时返回明确的业务错误，不再把空列表标记成检索成功。

## 3. 统一 HTTP 协议

所有 action 使用同一个入口：

```http
POST /paper_reading
Content-Type: application/json
```

前端发送的是 `PaperReadingRequest` 的 JSON。最小结构：

```json
{
  "action": "start_reading",
  "session_id": "",
  "paper_id": "",
  "content": "",
  "metadata": {}
}
```

HTTP 返回是 `ChannelMessage` 包裹结构，前端需要读取 `response.content`：

```json
{
  "session_id": "paper-reading-...",
  "channel": "web",
  "direction": "outbound",
  "mode": "paper_reading",
  "content": {
    "status": "ok",
    "action": "start_reading",
    "data": {},
    "session": {},
    "progress": {},
    "kg_update": {},
    "skill_outputs": []
  }
}
```

前端统一拆包建议：

```ts
type PaperReadingEnvelope = {
  session_id: string
  channel: 'web'
  direction: 'outbound'
  mode: 'paper_reading'
  content: PaperReadingActionResponse
}

type PaperReadingActionResponse = {
  status: 'ok' | 'error' | 'pending' | 'fork_active'
  action: string
  message?: string
  data: Record<string, unknown>
  session?: Record<string, unknown>
  progress?: Record<string, unknown>
  kg_update?: Record<string, unknown>
  skill_outputs?: Array<Record<string, unknown>>
  error?: string
}
```

错误响应统一：

```json
{
  "status": "error",
  "action": "upload_paper",
  "message": "PDF 解析失败: ...",
  "session_id": "",
  "error": "PDF 解析失败: ..."
}
```

## 4. 功能清单、触发时机与接口

### 4.1 `search_paper`

触发时机：用户在论文搜索框输入关键词并点击“搜索”。

请求：

```json
{
  "action": "search_paper",
  "session_id": "",
  "search_query": "graph neural network survey",
  "search_source": "all",
  "search_max_results": 10
}
```

后端流程：

`handler._handle_search_paper()` → `PaperPipeline.search()` → arXiv / Semantic Scholar → 去重 → 返回论文摘要列表。

返回 `content.data`：

```json
{
  "query": "graph neural network survey",
  "count": 2,
  "papers": [
    {
      "paper_id": "...",
      "title": "...",
      "authors": ["..."],
      "year": 2024,
      "abstract": "...",
      "source": "arxiv",
      "url": "...",
      "pdf_url": "...",
      "citation_count": null,
      "venue": ""
    }
  ]
}
```

前端承接：

- 搜索结果列表展示 `title/authors/year/source/citation_count/abstract`。
- 每条结果提供“打开 PDF / 导入阅读”按钮。
- 若有 `pdf_url`，点击导入时调用 `upload_paper`。

注意：当前环境未安装 `feedparser` 时，arXiv 搜索无法真实运行；项目依赖已声明。

### 4.2 `upload_paper`

触发时机：

- 用户点击“上传 PDF”并选择本地文件。
- 用户从搜索结果选择 `pdf_url` 导入。

本地 PDF 请求：

```json
{
  "action": "upload_paper",
  "session_id": "",
  "pdf_data": "BASE64_ENCODED_PDF"
}
```

URL PDF 请求：

```json
{
  "action": "upload_paper",
  "session_id": "",
  "pdf_url": "https://arxiv.org/pdf/xxxx.xxxxx"
}
```

后端流程：

`upload_paper` → `PDFParser.parse_bytes()` → 生成 `PaperMetadata` → `storage.save_paper()` → `storage.save_upload()` → `kg_builder.build_full_paper()` → `storage.save_kg()`。

返回 `content.data`：

```json
{
  "paper_id": "...",
  "title": "...",
  "authors": ["..."],
  "abstract": "...",
  "sections_count": 8,
  "sections": [
    {
      "section_id": "sec:1",
      "title": "1 Introduction",
      "level": 1
    }
  ],
  "parse_status": "done",
  "kg_build": {
    "new_nodes": 12,
    "new_edges": 10,
    "mode": "full_paper_once"
  }
}
```

前端承接：

- 保存 `paper_id` 到页面状态和本地缓存。
- 左侧 Outline 使用 `sections` 渲染。
- 顶部显示标题、作者、摘要。
- KG 面板显示 `kg_build` 构建摘要。
- 立即调用 `get_paper_detail` 获取完整正文和 PDF URL。

运行前置：

- `upload_paper` 真实解析依赖 `PyMuPDF` 的 `fitz` 模块。
- 当前验证环境缺少 `fitz`，因此真实 PDF 解析未完成；安装 `python -m pip install -e .` 后重跑验证。

### 4.4 `GET /paper_reading/uploads/{paper_id}.pdf`

触发时机：PDF viewer 需要重新加载已上传原文件。

请求：

```http
GET /paper_reading/uploads/{paper_id}.pdf
```

返回：

- `200 application/pdf`: PDF 文件。
- `404`: 未找到上传文件。
- `503`: storage 未初始化。

前端承接：

- 用 PDF.js、浏览器 `<iframe>` 或内置 PDF viewer 加载。
- URL 由 `get_paper_detail.data.pdf_url` 提供，不建议前端自行拼接。

### 4.5 `start_reading`

触发时机：

- 用户点击“开始阅读”。
- 用户点击左侧章节。
- 用户在右侧 AI 输入框提出“分析方法章节的数学推导”。
- fork 子会话中加载专项 Skill 后继续分析。

请求：

```json
{
  "action": "start_reading",
  "session_id": "",
  "paper_id": "paper-uuid",
  "target_section": "sec:3",
  "content": "请分析方法章节的数学推导"
}
```

后端完整流程：

1. `handler._handle_start_reading()` 读取或创建 session。
2. 从 `PaperReadingStorage` 加载 paper metadata 和 sections。
3. 如果 KG 不存在，调用 `kg_builder.ensure_full_paper_kg()` 一次性构建整篇 KG。
4. 根据 `target_section/current_section` 调 `kg_builder.get_revealed_subgraph()` 渐进展开 KG。
5. `_build_start_reading_context()` 组装 agent 输入上下文：
   - 论文元信息
   - 阅读状态
   - 论文目录
   - 当前章节正文
   - 已展开 KG 摘要
   - 用户问题
6. `run_agent_detailed()` 调用 `paper_reading_agent`。
7. `_active_skill_ids_for_context()` 决定默认 Skill：
   - active skills 非空：使用当前 session active skills。
   - experiment/result 章节：默认 `reading.critique_agent`。
   - conclusion 章节：默认 `reading.idea_generator`。
   - 其他章节：默认 `reading.method_analyst`。
8. `postprocess_agent_output()` 生成结构化 `skill_outputs`。
9. 更新 session progress。
10. 返回 agent 输出、进度、KG 和 Skill 结果。

返回 `content.data`：

```json
{
  "session_id": "...",
  "agent_response": "...",
  "model_calls": 1,
  "duration_ms": 1234.56,
  "current_section": "sec:3",
  "context": {
    "paper_loaded": true,
    "kg_mode": "full_paper_once_progressive_reveal",
    "active_skill_ids": ["reading.method_analyst"]
  },
  "revealed_kg": {
    "paper_id": "...",
    "current_stage": "method",
    "allowed_stages": ["abstract", "introduction", "method"],
    "nodes": [],
    "edges": [],
    "node_count": 0,
    "edge_count": 0,
    "cytoscape_elements": []
  },
  "kg_build": {
    "section_type": "existing",
    "new_nodes": 0,
    "new_edges": 0
  }
}
```

同级返回：

```json
{
  "session": {
    "session_id": "...",
    "paper_id": "...",
    "paper_title": "...",
    "state": "active",
    "current_section": "sec:3",
    "active_skills": ["reading.math_verifier"]
  },
  "progress": {
    "current_position": {
      "section_id": "sec:3",
      "paragraph_index": 0
    },
    "total_sections": 8
  },
  "kg_update": {
    "new_nodes": [],
    "new_edges": [],
    "updated_nodes": [],
    "fusion_events": []
  },
  "skill_outputs": [
    {
      "skill_id": "reading.method_analyst",
      "skill_name": "Method Analyst",
      "trigger": "auto",
      "output_type": "method_analysis",
      "content": {},
      "rendered": "### Method Analyst\n...",
      "kg_candidates": {
        "nodes": [],
        "edges": []
      },
      "parse_status": "parsed"
    }
  ]
}
```

前端承接：

- `data.agent_response`：右侧 AI 回复主卡片。
- `skill_outputs[]`：右侧 Skill 卡片，优先展示 `rendered`，需要结构化 UI 时读取 `content`。
- `data.revealed_kg.cytoscape_elements`：底部 KG 图谱。
- `progress`：左侧进度条、章节状态。
- `session.session_id`：保存到本地，用于后续恢复。

### 4.8 `fork`

- 用户高亮某个公式/概念/段落。

- 在弹窗中选择 `reading.math_verifier`、`reading.domain_expert` 等专项 Skill。

请求：

```json
{
  "action": "fork",
  "session_id": "parent-session-id",
  "fork_context": "被高亮的公式或段落文本",
  "fork_skills": ["reading.math_verifier"],
  "fork_question": "请逐步验证这段公式推导是否成立"

```

返回：

```json
{
  "status": "ok",
  "action": "fork",
  "data": {
    "fork_session_id": "child-session-id",
    "message": "分支已创建",
    "active_skills": ["reading.math_verifier"]
  }

```

前端承接：

- 打开 Fork 弹窗。
- 用 `fork_session_id` 作为弹窗内临时会话。
- 弹窗中继续调用 `start_reading`，`session_id` 使用 `fork_session_id`，`content` 使用用户问题。

## 6. KG 构建与展示

节点类型共 13 种：

```text
Problem, Method, Module, Baseline, Metric, Dataset, Experiment,
Figure, Concept, Limitation, Claim, RelatedWork, Insight
```

边类型共 9 种：

```text
motivates, extends, outperforms, depends_on, contradicts,
ablates, inspired_by, evaluated_on, contributes_to
```

当前 KG 策略：

- 上传或首次阅读时：`build_full_paper()` 一次性构建整篇 KG。
- 阅读过程中：`get_revealed_subgraph()` 根据当前章节阶段渐进返回可见子图。
- 前端无需自己做阶段过滤，直接渲染后端返回的 `revealed_kg.cytoscape_elements`。

阶段映射：

| 当前章节 | current_stage | 展开内容 |
|---|---|---|
| Abstract | `abstract` | Problem、Method 壳、核心 Concept |
| Introduction / Related Work | `introduction` | 引言、相关工作阶段节点 |
| Method / Approach / Model | `method` | 方法模块、依赖概念、贡献关系 |
| Experiment / Result | `experiment` | 实验、数据集、指标、评测关系 |
| Conclusion / Discussion | `conclusion` | Claim、Limitation、未来方向 |
| 其他 | `general` | 全部阶段 |

## 7. 前端推荐页面状态


推荐初始化流程：

## 9. 当前限制与前端注意事项

1. 当前没有独立论文精读前端，`gateway/static/app.js` 仍是通用聊天页；前端必须新建论文精读页面或模块。
2. 前端不能继续只发送 `{content: "..."}`，必须按 `action` 构造完整请求体。
3. 所有响应需要读取 `envelope.content`，不要把 HTTP 顶层 `session_id` 当作业务 data。
4. 真实 PDF 解析依赖 `PyMuPDF`；缺少依赖时 `upload_paper` 会失败。
5. arXiv 搜索依赖 `feedparser` 和网络。
6. Gateway 启动依赖 `fastapi/uvicorn`。
7. 当前没有 SSE/流式输出，`start_reading` 是一次性返回。
8. 当前没有用户个人知识库写入 action；Skill 输出里的 `kg_candidates` 只能用于前端展示或后续扩展。
9. 当前没有前端自定义 Skill CRUD；后端仅支持加载已有 8 个 Skill。
10. pause/resume 保存 session/checkpoint，但前端仍需保存最近的 `session_id/paper_id` 以便下次恢复。

## 10. 给前端的最小联调顺序

1. 安装依赖并启动 gateway。
2. 实现 `callPaperReading(actionBody)`，统一拆 `response.content`。
3. 先联调 `upload_paper` 或手动准备已保存 paper。
4. 联调 `get_paper_detail` + PDF viewer。
5. 联调 `start_reading`，展示 AI 回复、Skill 卡片、KG 图谱。

7. 联调 `fork/start_reading/merge` 弹窗流程。
8. 联调 `kg_query` 问答和图谱高亮。
9. 联调 `pause_reading/resume_reading/get_session_state/get_progress` 页面恢复。
