# GitHub 分支开发流程

## 一、长期维护分支

项目长期保留两个分支：

### `main`

`main` 用于保存稳定、可以正常运行和演示的版本。

只有当 `develop` 中的功能经过整体测试并确认稳定后，才合并到 `main`。

### `develop`

`develop` 用于日常开发和功能集成。

所有新功能和问题修复完成后，先合并到 `develop`，再在 `develop` 中进行统一测试。

---

## 二、临时开发分支

每开发一个新功能或修复一个问题，都应从最新的 `develop` 创建一个临时分支。

常见分支类型如下：

| 分支类型 | 用途 | 示例 |
|---|---|---|
| `feat/功能名称` | 开发新功能 | `feat/paper-search` |
| `fix/问题名称` | 修复问题 | `fix/api-error` |
| `docs/文档名称` | 修改文档 | `docs/deployment-guide` |
| `refactor/重构内容` | 重构代码 | `refactor/agent-workflow` |

临时分支只负责一个明确的功能或问题，不要直接在 `main` 或 `develop` 上编写功能代码。

---

## 三、标准开发流程

```text
更新本地 develop
        ↓
从 develop 创建临时分支
        ↓
在临时分支中开发
        ↓
完成本地测试
        ↓
提交并推送临时分支
        ↓
创建 PR，合并到 develop
        ↓
在 develop 中进行集成测试
        ↓
删除已完成的临时分支
```

具体要求：

1. 创建新分支前，先确保本地 `develop` 已更新到远程最新版本。
2. 一个功能或一个问题对应一个临时分支。
3. 开发完成后，先在本地测试。
4. 测试通过后，将分支推送到 GitHub。
5. 创建 PR，将临时分支合并到 `develop`。
6. 合并后，在 `develop` 中进行整体测试。
7. 功能确认无误后，及时删除本地和远程临时分支。

---

## 四、分支删除规则

功能分支、修复分支等都属于临时分支。

当一个分支已经：

- 开发完成；
- 测试通过；
- 合并到 `develop`；

就应及时删除，避免仓库中积累大量无用分支。

项目中长期保留的分支只有：

```text
main
develop
```

---

## 五、整体版本流转

```text
临时开发分支
      ↓
   develop
      ↓
     main
```

- **临时开发分支**：负责单个功能、问题修复或代码调整。
- **`develop`**：负责多个功能的集成和测试。
- **`main`**：负责保存稳定、可运行、可演示的版本。
