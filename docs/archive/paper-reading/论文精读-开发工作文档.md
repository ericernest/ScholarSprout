### 1.3 知识图谱渐进构建流程

```
用户阅读进度                KG 构建动作
─────────────────────────────────────────────
Abstract 读完          → 创建 Problem + Method(壳) 节点
Introduction 读完      → 创建 Baseline 节点集 + RelatedWork 节点集
                         连接 inspires/extends 边
Method §3.1 读完       → 创建 Module(Encoder) + depends_on Concept 边
Method §3.2 读完       → 创建 Module(核心创新) + contributes_to(core_innovation) 边
Method §3.3 读完       → 创建 Module(辅助模块) + contributes_to 边
Experiment 读完        → 创建 Experiment + Dataset + Metric 节点集
                         连接 outperforms/ablates/evaluated_on 边
Conclusion 读完        → 创建 Limitation + Claim 节点集 + contradicts 边
─────────────────────────────────────────────
多篇论文阅读后          → CrossPaperFusion: 合并同名节点、检测演化链和矛盾
```

### 1.4 Fork/Merge 分支流程

```
主阅读流 (parent session)
  │
  ├── POST /paper_reading {action: "fork", fork_context: "公式 (3.2)",
  │                         fork_skills: ["reading.math_verifier"]}
  │   └─ ForkMergeManager.create_fork()
  │       └─ 返回 fork_session_id → 前端切换到子会话
  │
  ├── [子会话中] POST /paper_reading {action: "start_reading",
  │                                     session_id: fork_session_id, ...}
  │   └─ 使用专用 skill (如 math_verifier) 独立对话
  │
  ├── POST /paper_reading {action: "merge",
  │                         merge_session_id: fork_session_id}
  │   └─ ForkMergeManager.merge_fork()
  │       └─ 提取 fork 关键发现 → 返回主会话 → 标记 fork 为 completed
  │
  └── 继续主阅读流
```

**实现模式**（参考 `paper_reading/kg/builder.py` 的 `parse_extraction_response()`）:

```python
# paper_reading/skills/method_analyst.py 示例
import json, re

def parse_method_analyst_output(agent_text: str) -> dict | None:
    """从 Agent 输出中解析方法论分析结果。"""
    text = agent_text.strip()
    # 1. 尝试直接 JSON 解析
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        pass
    # 2. 尝试 Markdown 代码块提取
    match = re.search(r'```(?:json)?\s*([\s\S]*?)\s*```', text)
    if match:
        try:
            return json.loads(match.group(1))
        except json.JSONDecodeError:
            pass
    # 3. 尝试找到 JSON 对象边界
    start = text.find('{')
    end = text.rfind('}')
    if start >= 0 and end > start:
        try:
            return json.loads(text[start:end + 1])
        except json.JSONDecodeError:
            pass
    return None
```

对于长时间的 Agent 执行，支持 `text/event-stream` 逐步返回。需要扩展 `process_channel_input` 或在 `ChannelMessage.metadata` 中传递 `stream: true`。

#### 4.3.4 Web UI（三栏式阅读界面）
docx 中描述的三栏布局（左导航 + 中正文 + 右 AI 面板 + 底部 KG 可视化）作为独立计划。

#### 4.3.5 测试套件
`tests/test_paper_reading/` 目录和 `verify_imports.py` 已创建，需要编写全面的单元测试和集成测试。

### 5.6 常见问题排查

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| `ModuleNotFoundError: No module named 'paper_reading'` | 项目未安装或 PYTHONPATH 未设置 | `pip install -e .` 或 `PYTHONPATH=. python ...` |
| `ModuleNotFoundError: No module named 'fitz'` | PyMuPDF 未安装 | `pip install PyMuPDF` |
| `ModuleNotFoundError: No module named 'networkx'` | networkx 未安装 | `pip install networkx` |
| Agent 返回空响应 | LLM 配置错误（api_key/base_url/model_name） | `novicesynapse doctor` 检查配置 |
| PDF 解析后章节为空 | PDF 是扫描版（图片格式，无文本层） | 需要使用 OCR 预处理，当前不支持 |
| Skill 未生效 | SKILL.md 文件不在正确的 category 目录下 | 确认文件在 `skills/builtin/reading/{name}/SKILL.md` |
| Fork 会话找不到 | 父会话未被持久化 | 确保 `session_manager` 传入了 `PaperReadingStorage` 实例 |
| KG 构建未触发 | `kg_build` tool 的依赖注入未设置 | 确认 `gateway/app.py` 中调用了 `set_kg_engine()` 和 `set_kg_builder()` |
