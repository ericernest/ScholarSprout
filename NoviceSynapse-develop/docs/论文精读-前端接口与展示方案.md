# 论文精读前端接口与展示方案

> 日期: 2026-07-22  
> 目标: 基于当前已经实现的论文精读后端，给出前端布局、按钮交互、请求体、后端返回结构、可视化承接方式和完整输入输出流程。  
> 需求来源: `论文精读.docx` 中的论文流水线、Skill 系统、动态 KG、KG 问答、三栏式阅读界面、Fork 弹窗等场景。  
> 当前覆盖范围: 只覆盖已经实现或已有接口基础的后端能力；用户个人知识库、自定义 Skill 编辑、SSE 流式输出等未实现能力会在文末标为后续扩展。

## 1. 当前后端能力清单

论文精读当前统一使用：

```http
POST /paper_reading
Content-Type: application/json
```

已实现 action：

| action | 场景 | 是否调用 Agent | 前端主要用途 |
|---|---|---:|---|
| `search_paper` | 搜索论文 | 否 | 搜索结果列表 |
| `upload_paper` | 上传 PDF 并解析 | 否 | 本地/URL PDF 上传、生成 Outline、触发整篇 KG 构建 |
| `get_paper_detail` | 获取完整论文数据 | 否 | 页面刷新后恢复论文正文和 PDF URL |
| `start_reading` | 开始/继续阅读 | 是 | 当前章节精读、Skill 输出、KG 渐进展开 |
| `pause_reading` | 暂停阅读 | 否 | 保存 checkpoint |
| `resume_reading` | 恢复阅读 | 否 | 恢复 session 状态 |
| `fork` | 创建分支探索 | 否 | 弹窗加载专项 Skill |
| `merge` | 合并分支 | 否 | Fork 结果回到主阅读流 |
| `load_skill` | 手动加载 Skill | 否 | 开启右侧专家卡片 |
| `unload_skill` | 手动卸载 Skill | 否 | 关闭专家卡片 |
| `kg_query` | KG 驱动问答 | 可用 LLM 组织答案 | 图谱问答、路径和 evidence 展示 |
| `get_session_state` | 获取会话状态 | 否 | 页面初始化/恢复 |
| `get_progress` | 获取阅读进度 | 否 | 左侧进度条 |

额外已实现 HTTP 文件接口：

```http
GET /paper_reading/uploads/{paper_id}.pdf
```

用途：返回后端保存的原始 PDF，支持 PDF.js 或 iframe 在页面刷新后恢复显示。

## 2. 统一前端架构

推荐单独实现论文精读页面，而不是复用普通聊天页。

建议文件：

```text
gateway/static/paper-reading.html
gateway/static/paper-reading.js
gateway/static/paper-reading.css
```

建议路由后续新增：

```http

```

当前如果暂不改后端路由，也可以先在现有 `/app` 中通过 mode 进入，但论文精读 UI 本身应独立成工作台。

## 5. 统一请求与响应拆包

所有 action 请求都发完整 JSON。

```js
async function callPaperReading(body) {
  const response = await fetch("/paper_reading", {
    method: "POST",
    headers: {"Content-Type": "application/json"},
    body: JSON.stringify(body),
  });
  const envelope = await response.json();
  const payload = envelope.content;
  if (payload.status === "error") {
    throw new Error(payload.message || payload.error || "paper_reading failed");
  }
  return { envelope, payload };
}
```

响应外壳：

```json
{
  "session_id": "...",
  "channel": "web",
  "direction": "outbound",
  "mode": "paper_reading",
  "content": {
    "status": "ok",
    "action": "...",
    "data": {}
  }
}
```

前端只把 `envelope.session_id` 作为消息通道 id；业务状态以 `payload.data.session_id` 或 `payload.session.session_id` 为准。
