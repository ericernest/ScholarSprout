# 研见 · SeeFurther

**See Further into Research.**

> 从一篇论文，看见一个领域。

研见（SeeFurther）是一款面向科研学习的本地优先 AI 研究工作台。它把“提出问题、建立领域背景、筛选论文、精读原文、沉淀笔记”串成一条连续路径，让论文不再只是需要读完的文件，而是可以继续追问、验证和连接的研究入口。

## 为什么是研见

面对一个陌生方向，真正困难的通常不是找到一篇论文，而是回答几个连续的问题：这个领域从哪里开始？哪些概念必须先掌握？哪些论文代表关键转折？一篇 Survey 引用了哪些值得继续追踪的工作？一篇论文的方法、实验和局限应该如何快速定位？

研见将这些问题拆成可操作的研究阶段：

1. **领域入门**：先梳理前置知识，再理解领域的发展路径。
2. **论文发现**：以 Survey 为入口，补充由 Survey 引用的代表性工作。
3. **论文精读**：沿着导读地图进入实验重点，并对原文选区直接提问。
4. **研究对话**：在同一工作台中继续追问、比较、整理和回看。

## 核心能力

### 对话工作台

适合从一个研究问题开始，也适合围绕已导入论文继续追问。

- 支持 Markdown、代码块和表格等研究型内容展示
- 流式返回长回答，实时看到任务进度
- 推理过程可折叠，保留信息密度而不打断阅读
- 长任务支持中断、失败重试和继续操作
- 对话、论文和领域任务共享本地运行上下文

<!-- 截图占位：对话页面 -->

### 领域入门

领域入门不是简单的搜索结果列表，而是一份可以沿着阅读的研究地图，包含：

- **前置知识梳理**：进入领域前需要了解的概念、方法和基础工作
- **领域发展路径**：从早期问题到关键方法和当前方向的演进关系
- **学习路径**：按照理解成本和依赖关系组织建议顺序
- **相关论文推荐**：说明论文为什么值得读，以及它在路径中的位置

论文推荐遵循“**Survey 主导**”规则：最多 3 篇 Survey，再补充最多 3 篇由这些 Survey 引用的论文。这样既保留领域全景，也避免入门页面被过长、无层次的论文列表淹没。

<!-- 截图占位：领域入门页面 -->

### 论文精读

论文精读页面围绕“快速建立结构化理解”设计：

- 导入并解析本地 PDF
- 生成论文的**导读地图**，快速定位章节与论证关系
- 提取**实验重点分析**，关注设置、对比、指标和结论
- 对原文任意选区发起**原文选区提问**，让问题绑定证据上下文
- 保存高亮、批注和阅读进度，支持回到上次阅读位置

### 本地优先与可扩展

v1 面向个人电脑本地部署：数据、模型配置和 API Key 由本地后端处理，前端静态资源由本地网关提供，不需要额外启动前端服务。前端采用 Vue 3 + TypeScript + Vite 多页面结构，为未来接入集中式网页服务保留清晰边界。

## 快速开始

### 环境要求

- Python 3.11+
- Node.js 18+（仅在修改前端时需要）
- Windows 或 Linux

### 安装后端

```bash
python -m pip install -e .
```

### 启动研见

```bash
novicesynapse gateway --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000/> 即可使用。`novicesynapse` 是当前 v1 的命令行入口名称，产品名称为“研见 · SeeFurther”。

### 配置模型

在“设置”页面配置模型提供商、模型名称和 API Key。默认数据目录位于当前用户目录下的 `.novicesynapse`，不会把具体用户名写死在代码中；需要时可由后端配置覆盖。

## 页面导航

| 页面 | 地址 | 主要用途 |
| --- | --- | --- |
| 对话 | `/app` | 研究问答、任务流和上下文对话 |
| 领域入门 | `/app/domain-onboarding` | 前置知识、发展路径和论文推荐 |
| 论文精读 | `/app/paper-reading` | 导读地图、实验分析和选区提问 |
| 论文库 | `/library` | 已导入论文、来源和阅读状态 |
| 设置 | `/settings` | 模型、数据目录和运行配置 |

## 工作方式

```text
研究问题
   ↓
领域入门 → 前置知识 / 发展路径 / Survey 论文清单
   ↓
论文精读 → 导读地图 / 实验重点 / 原文选区提问
   ↓
对话与笔记 → 比较、追问、回看和继续研究
```

浏览器请求由 FastAPI 网关接收，领域入门、论文精读、对话和设置分别由现有后端处理器提供能力；前端负责页面呈现、交互状态和 API 调用。保持这个边界可以让本地版足够轻量，也方便未来把后端替换为集中式服务。

## 前端开发

前端源码位于 `webui/`，采用 Vue 3 + TypeScript + Vite 多页面结构。网关运行时使用已构建的 `gateway/static/app-v2/` 静态资源。

```bash
cd webui
npm install
npm run build
```

生成资源后重新启动网关即可查看页面变化。

## 版本边界

当前版本是面向个人电脑的 v1 本地部署版，重点是论文导入、领域入门、论文精读和研究对话。集中式账号、团队协作、云端任务调度等能力属于后续版本的扩展方向，不影响当前本地工作流。
